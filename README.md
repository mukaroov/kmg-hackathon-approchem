# Глава → курс: конвейер, сборщик и шаблон демо-курса

**Конвейер** принимает главу книги (`.md` или `.pdf`), отправляет её языковой модели по API и получает **учебный слой** (JSON). Слой проверяется, а из него сборщик `node build/build.mjs` делает демо-курс. Вручную ничего не верстается: чтобы поправить факт, правят слой и пересобирают курс.

## Конвейер: быстрый старт

Нужен Node.js 18 или новее, зависимостей нет.

1. Скопируйте `.env.example` в `.env`. Поставщик модели — `LLM_PROVIDER`: `agent` или `cli` работают без платного API (см. «Работа без платного API» ниже), `mistral` и `openai-compatible` — по ключу, `stub` — заглушка.
2. Одна команда на главу:

```
node pipeline/run.mjs "books md/train_latyshova.md" --pages 90-108 --id latyshova-auto
node pipeline/run.mjs glava.pdf --page-start 474        # PDF: номер страницы книги для первой страницы файла
node pipeline/run.mjs glava.md --provider stub          # проверка каркаса без модели и без ключа
```

Или загрузка главы со страницы: двойной щелчок по `start.cmd` (macOS и Linux: `./start.sh`). Скрипт запускает сервер конвейера и открывает в браузере `http://127.0.0.1:8787/`: там форма загрузки `.md` или `.pdf`, ход работы в реальном времени и список готовых курсов. То же из терминала:

```
node pipeline/server.mjs --open   # без --open страница не открывается сама; контракт API для фронтенда — pipeline/API.md
```

Сервер принимает загрузку только со своей страницы и с адресов из `CORS_ORIGINS`: чужой сайт в браузере не может запустить конвейер на этом компьютере.

Результат: курс `dist/<глава>/index.html`, слой `layer/<глава>/`, выгрузки организаторов `export/<глава>/` (слой, покрытие, маршрутизация), отчёт прогона `work/jobs/<задача>/report.json`, строки метрик в `logs/metrics.csv`.

### Что делает конвейер

| Этап | Что происходит | Где в коде |
|---|---|---|
| Приём | md с метками `<!-- page N -->` берётся как есть. PDF распознаётся Mistral OCR постранично, рисунки сохраняются и описываются моделью с поддержкой изображений. Глава делится на единицы: абзац, рисунок, формула, таблица, пример, задача, заголовок | `pipeline/lib/ingest.mjs`, `build/lib/source.mjs` |
| План шагов | Модель разбивает главу на части и шаги. Каждой единице назначается шаг, задаются типы трудности, пороговые идеи и предпосылки. Конвейер проверяет, что ни одна единица не потеряна; если потеряна — модель исправляет план, а остаток конвейер назначает сам и пишет об этом в отчёт | `pipeline/lib/stages.mjs`, `pipeline/prompts/outline.md` |
| Узлы | На каждый шаг один запрос: суть, объяснение со страницами, утверждения с дословными цитатами, примеры, числа, формулы, таблицы, понятия, ошибка новичка, мост к данным, аналогии с границей, маршрутизация с баллами видеоёмкости, рисунок, задания, карточка | `pipeline/prompts/node.md`, `pipeline/lib/schemas.mjs` |
| Проверки и исправление | Цитата должна стоять на своей странице по правилу организаторов. Проверяются страницы, задания (ответ среди вариантов), числа (есть ли в главе), длина фраз и заголовков, обязательные блоки. Что можно, исправляется без модели: страница цитаты, нотация индексов. Остальное модель исправляет по списку ошибок, до `REPAIR_ROUNDS` кругов | `pipeline/lib/checks.mjs`, `pipeline/prompts/repair.md` |
| Модуль проверки | Модель сверяет пересказ с цитатами по типам закладок ТЗ: сверхобобщение, переворот знака, измеренное вместо выведенного, потеря условия и другие. Значимые ошибки исправляются одним кругом, всё записывается в отчёт | `pipeline/prompts/verify.md` |
| Добор заданий | Если в главе меньше 15 заданий или меньше 4 типов, конвейер добирает их в шагах с наименьшим числом заданий | `pipeline/prompts/tasks.md` |
| Запись и сборка | Слой пишется в `layer/<глава>/`, курс собирается сборщиком со всеми его проверками | `pipeline/lib/assemble.mjs` |

Свойства, которые требует ТЗ:

- **Модель заменяема.** Поставщик задаётся в `.env`: `mistral`, любой API, совместимый с OpenAI (`openai-compatible`), или `stub`. Схемы ответов простые: если поставщик не принимает строгую схему, конвейер сам переходит на JSON со схемой в промпте.
- **Доменный пакет отдельно от движка.** Предметное лежит в `domain/<домен>/`: `domain.json`, заблуждения, чек-лист физики, легенда. Для новой области (например, бурения) собирается новый пакет: `--domain drilling`. Промпты от домена не зависят.
- **Воспроизводимость и стоимость.** Ответы модели кешируются в `cache/llm/`, поэтому повторный прогон той же главы бесплатен, а после сбоя прогон продолжается с места остановки. Токены по этапам пишутся в `logs/metrics.csv`. Лимит бесплатного плана Mistral (1 запрос в секунду) соблюдает очередь с повтором при ответе 429.
- **Ручные правки не теряются.** Если слой правили после прогона, повторный прогон не перезапишет его без `--force`, и правку нужно записать в `logs/manual_edits.csv`. Слои, сделанные вручную (`layer/latyshova-v`), конвейер не трогает: пишет рядом, в `<id>-auto`.
- **Покрытие.** В каждом узле записано, какие единицы главы назначил ему план (`units`). Таблица покрытия объединяет план и независимую сверку текста; единицы, которые сверка не подтвердила, выделены отдельной проверкой: их могли пересказать слишком общо.

### Работа без платного API

- `LLM_PROVIDER=agent` — запросы модели кладутся файлами в `work/agent-queue/`: `<id>.prompt.md` (полный промпт со схемой ответа) и `<id>.request.json`. Любой агент (Claude Code, Codex CLI) пишет ответ `<id>.response.json` по схеме; конвейер ждёт его до `AGENT_TIMEOUT_MIN` минут, неразобранный ответ возвращает с `<id>.error.txt`, отработанные запросы переносит в `done/`. Инструкция для агента — `work/agent-queue/README.md`. Так собраны главы Кузнецова и Басниева.
- `LLM_PROVIDER=cli` — конвейер сам вызывает авторизованный CLI: `LLM_CLI=claude` (`claude -p --json-schema`) или `codex` (`codex exec --output-schema`); модель CLI — `LLM_CLI_MODEL` (пусто — модель CLI по умолчанию), путь — `LLM_CLI_PATH`. Режим `codex` на реальном CLI не проверялся.
- Ответы кешируются так же, как в API-режиме: повторный прогон той же главы берёт их из `cache/llm/`.

### Ролик к шагу

```
node pipeline/video.mjs layer/<глава> <id шага> [--format 9:16|16:9] [--from-spec] [--no-voice]
```

Модель пишет спецификацию сцены по схеме движка (`video/scene.schema.json`); конвейер проверяет её по ТЗ (длительность, крючок до 4 с, пауза на предсказание, утверждение и страница у каждого сегмента, подписи до 8 слов, озвучка без цифр и в темпе). Детерминированный движок `video/video_engine.py` (Python 3.12, numpy, matplotlib, pydantic 2) рисует кадры по стайлгайду `domain/geo/video_style.json`; голос — Windows SAPI (`video/tts.ps1`, голос «Microsoft Irina Desktop»), громкость −16 LUFS, субтитры `.vtt`, постер и паспорт по `schemas/passport.schema.json`. Ролик кладётся в `layer/<глава>/assets/media/<шаг>/` и подключается к узлу. `--from-spec` пересобирает ролик из сохранённой спецификации без модели. Нужны `PYTHON_PATH` и `FFMPEG_PATH` в `.env`.

Шаблоны движка: `geological_evolution`, `well_log_sync`, `crossplot_cutoff`, `pressure_wave_2d` (режим `well_mode: "rate"` — постоянный дебит, давление точно по основной формуле упругого режима через −Ei, с логарифмическим приближением и границей x = 0,01), `formula_dynamic_plot`.

### Модуль проверки внешнего пакета

```
node pipeline/review.mjs <package.json> [--chapter <md главы>] [--out <ответ.json>]
```

Вход — пакет по `schemas/review_package.schema.json`, выход — замечания по `schemas/review_output.schema.json` (`work/review/<пакет>/answer.json` и отчёт `report.json`). Сначала автоматическая сверка: цитата дословно на указанной странице, «всегда/любой» и числа, которых нет в цитате, переворот направления, ослабленное условие, лишняя фраза сверх цитаты. Затем модель судит группы элементов по тексту страниц главы; кадры она смотрит по файлам PNG вместе со спецификацией сцены и фразой закадра в этот момент. Замечания проверяются: цель из пакета, страница в главе, цитата дословно на странице, одно замечание на цель.

Контрольный пакет `ctrl_vendelshtein` (ключ открыт только после прогона): найдено полностью 19 из 21 ошибки, 95 % по весу, ложных тревог 0; пропущены C026 (дописанная фраза шире главы) и C037 (условие «низкая глинистость» ослаблено до «умеренной»). После прогона в сверку добавлены сигналы на оба случая — на контрольном пакете это уже не проверка. Результат — `work/review/ctrl_vendelshtein/score.txt`.

## Как открыть курс

Откройте двойным щелчком `dist/index.html` (список глав) или сразу `dist/latyshova-v/index.html`. Сервер и вход не нужны, всё работает с `file://`. В списке есть и курсы, которые собрал конвейер.

Внизу списка — блок «Собрать курс из своей главы». Курсы открываются без сервера, а сборка новой главы идёт через локальный конвейер: блок проверяет, запущен ли он, и даёт ссылку на страницу загрузки или подсказку, как его запустить (`start.cmd`). Прогресс, ответы, отметки карточек и место, где вы остановились, сохраняются в `localStorage` этого браузера.

Каждая глава лежит в своей папке `dist/<глава>/` со всеми файлами: шрифтами, рисунками, роликами. Папку можно отдать отдельно.

## Как собрать курс из слоя

Нужен Node.js 18 или новее, зависимостей нет.

```
node build/build.mjs                    # собрать все главы из layer/*
node build/build.mjs layer/latyshova-v  # собрать одну главу
node build/build.mjs --check            # только проверить слой
node tools/serve.js dist 8092           # по желанию: локальный сервер для разработки
```

Сборщик проверяет слой по требованиям ТЗ и печатает отчёт. Тот же отчёт виден в курсе на странице «Источник», а полный список замечаний лежит в `dist/<глава>/build-report.json`.

Та же команда выгружает слой в общие форматы организаторов: `export/<глава>/layer.json` (схема `schemas/node.schema.json`) и `export/<глава>/coverage.json` (таблица покрытия, `schemas/coverage.schema.json`). Перед записью экспорт проверяется по схемам, а цитаты и числа — по выданному md главы.

## Схема узла (`strata.layer/1`)

Обязательные поля отмечены звёздочкой. Пустые блоки в курсе не показываются.

| Поле | Блок страницы шага | Формат |
|---|---|---|
| `id`* | — | устойчивый идентификатор, например `gis.v20.crossplot.04` |
| `title`* | Заголовок для новичка | 3–7 слов |
| `bookTitle`*, `bookShort` | Полное название из книги рядом | строка |
| `pages`* | «с. N–M» в шапке | `[97, 98]` |
| `difficulty`, `route`, `dataDecision` | Тип трудности, формат по маршрутизации, флаг шага «решение на данных» | `["Н","Р"]`, `{format, why}`, `true` |
| `essence`* | Суть | 2–3 фразы, первая — главное |
| `how`* | Как это работает | `[{text, page, claims:["c1"], hyp?}]`, фразы до 20 слов |
| `procedure` | По шагам | `{intro, page, items:[{text, page}]}` |
| `examples` | Разбор примеров из главы | `[{id, title, page, given, steps[], result, note?}]` |
| `numbers` | Цифры и условия | `[{name, value, cond, page}]` |
| `formulas` | Формулы (только из главы) | `[{expr, no, page, vars:[{s, m, u}], note}]` |
| `tables` | Таблицы книги целиком | `{title, page, head, rows, num, fixes:[{r, c, was}], notes, big}` |
| `glossary`* | Новые понятия | `[{term, en, def, page}]` |
| `mistake`* | Частая ошибка | `{wrong, right, page}` |
| `data`* | Что это значит для данных | `{input[], output[], breaks[]}`; пункт `{text, hyp:true}` помечается как гипотеза модели |
| `analogy`* | Аналогия с границей | `{text, limit}` |
| `figures`* | Иллюстрации (минимум одна) | `{id, kind: widget/scan/image, widget?, src?, class: A–D, place: top/examples/end, caption, origin, alt}` |
| `media` | Ролики | `{kind, src, poster, title, format, duration, page, vertical, ask:{at, q, options, answer, feedback[]}, remedial}` |
| `bookTasks` | Задачи из книги | `[{no, text, need, page}]` |
| `claims`* | Источник | `[{id, kind, sourceKind, text, quote, page, quoteMd?}]`: `kind` — `observation` / `inference` / `assumption` (наблюдение, вывод, допущение); `sourceKind` — `text` / `formula` / `table` / `figure_caption`; `text` пишет модель, `quote` — слова автора с исправленными индексами для курса; `quoteMd` — дословный текст md, если сборщик не находит его сам |
| `tasks`* | Проверь себя | см. ниже |
| `card`* | Карточка повторения | `{front, back}` |
| `threshold` | «пороговая идея» в шапке шага | `true` / `false` |
| `whyHere` | «Почему этот шаг здесь» в блоке «Связи шага» | строка |
| `layers` | только в экспорте | `{mechanism, practice, nuances, deeper[]}`; `topic` и `main` экспорт берёт из `bookTitle` и `essence` |
| `itAnalogy` | ИТ-аналогия в блоке «Аналогия» | `{text, limit}` |
| `nowPractice` | Как это делается сейчас (пометка «вне книги») | строка или `null` |
| `inefficiency` | Где здесь ручной труд | `{inputs, manualSteps, judgment, time, errors}` или `null` |
| `decision` | Решение на данных | `{features[], rule, conclusion, counterexample?}` или `null` |
| `mistake.ref` | связь `refutes_misconception` в экспорте | id заблуждения организаторов `misc.*` или `null` |
| `units` | только в покрытии | единицы главы, которые план конвейера назначил шагу: `["p095.03", …]` |
| `route.video_scores`, `route.template` | только в экспорте маршрутизации | баллы видеоёмкости 0–2 (`time`, `invisible`, `scale`, `counterintuitive`, `cause_effect`) и шаблон сцены |

Все тексты, кроме цитат, экспорт помечает `by_model: true`; `nowPractice` — ещё и `hypothesis: true`, потому что в книге его нет.

Разметка внутри строк: `ρ_{вп}` — нижний индекс, `10^{−3}` — верхний, `[[термин]]` или `[[термин|как показать]]` — термин со всплывающим объяснением из глоссария, `**жирный**`.

**Задания.** У каждого задания есть `id`, `type`, `explain` (одна фраза) и `claim` — ссылка на утверждение узла. Типы:

- `single` — `q`, `options[]`, `answer` (номер варианта);
- `multi` — `q`, `options[]`, `answer` (массив номеров);
- `order` — `q`, `items[]` в правильном порядке; курс перемешивает их сам; перетаскивание работает мышью, пальцем (за «ручку») и стрелками с клавиатуры;
- `blank` — `q`, `text` с `___`, `answer` — массив допустимых ответов;
- `calc` — `q`, `answer` (число), `tol` (допуск, доля), `unit`.

Необязательное поле `hints[]` — свои подсказки. Кроме них курс сам добавляет две: где искать ответ (страница утверждения) и само опорное утверждение.

## Что проверяет сборщик

- заданий не меньше 15, типов не меньше 4 из 5; у каждого задания есть ссылка на утверждение и пояснение в одну фразу;
- карточка на каждом узле; не меньше одной иллюстрации на шаг; в каждой части есть рисунок класса A или B;
- обязательные блоки в каждом шаге; заголовок 3–7 слов; суть 2–3 фразы;
- у каждого абзаца «Как это работает» есть страница, фразы не длиннее 20 слов;
- у каждого утверждения есть дословная цитата и страница, все страницы — в пределах главы;
- у каждой аналогии названа граница; есть шаг «решение на данных»;
- граф связей без циклов; шаги идут в порядке графа (сборщик сам переставит шаг, если предпосылка стоит позже следствия);
- размер курса без видео — не больше 30 МБ;
- экспорт слоя и таблицы покрытия соответствует схемам организаторов;
- цитата лежит в md главы на указанной странице по правилу организаторов: дословно, без учёта пробелов, переносов и регистра. Если цитата в слое записана с исправленными индексами (`ρ_{п}` вместо распознанного `ρn`), сборщик сам находит её дословный текст в md и кладёт в экспорт его; совпадение ниже 0,9 попадает в замечания «проверить глазами»;
- каждое число шага, заданий и карточки есть в главе; отдельно считаются числа, найденные не на страницах шага, и числа, которых в главе нет вовсе (учебные числа и результаты расчётов);
- покрытие: глава делится на единицы (абзац, рисунок, формула, таблица, пример, задача, заголовок), и каждая единица сопоставляется с узлами по цитатам, номерам примеров, задач, таблиц, рисунков и формул, по числам и словарю узла. Описания рисунков, которые модель вставила в md при извлечении (`━━━ FORMAT …`), считаются частью рисунка. Сопоставление автоматическое: оно показывает, на какие единицы слой опирается, но не заменяет сверку с ключом идей главы.

## Известные ограничения

- Легенда цветов собрана до выдачи стайлгайда организаторов и с ним расходится. Чтобы перейти на стайлгайд, замените значения в `domain/geo/legend.json` цветами из `пакет_вводных/03_стайлгайд/styleguide.json` и пересоберите.
- Рисунки 69 и 70 перерисованы кодом приближённо: кривые рис. 69 сняты со скана с точностью около ±10 %, рис. 70 проведён через числа автора. Ответы примеров 46, 47, 49, 50 и 53 на перерисовках совпадают с авторскими.
- В курсе ещё стоят сканы рисунков и страниц книги; схема иллюстраций организаторов такого происхождения не допускает.
- Задания, иллюстрации и паспорта роликов в форматы организаторов пока не выгружаются. Маршрутизация выгружается для глав, где у шагов есть баллы видеоёмкости, то есть для собранных конвейером.
- Слои Кузнецова и Басниева собраны в режиме `agent`: ответы на запросы конвейера писал Claude через очередь файлов. Прогона на ключе Mistral или Gemini целиком не было (бесплатные квоты не выдержали главу), поэтому токены и время для API-режима не измерены.
- Ролики: озвучка через Windows SAPI работает только на Windows; запасного русского голоса нет. Проверка озвучки распознаванием речи не сделана. В стайлгайде нефть и глина — оба зелёные.
- Рисунки книги из PDF сохраняются в `layer/<глава>/source-images/` и описываются моделью, но кодом не перерисовываются. В курсе у шага, собранного конвейером, стоит рисунок-схема, построенная кодом по тексту: цепочка или таблица применимости.
