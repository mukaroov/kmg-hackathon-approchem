# Учебный портал KMG · передача фронтенда

Распакуйте архив целиком и откройте `dist/index.html` в браузере. Файлы стилей, сценарии, изображения и видео должны оставаться рядом с HTML в исходной структуре. Для разработки из корня проекта можно запустить `python -m http.server 8080 --directory dist` и открыть `http://localhost:8080`. При работе через файл и через HTTP браузер может использовать разные хранилища.

## Данные и интерфейс

- `dist/content.js` публикует каталог `window.COURSES`. В нём находятся стабильные идентификаторы курсов, шагов и вопросов, фрагменты источников, задания и пояснения. Движок генерации курса можно подключить на этом уровне.
- `dist/media.js` предоставляет `window.MEDIA` с выпусками, локальными видеофайлами, моментами выбора и объяснениями вариантов. Маршруты шортсов используют идентификаторы выпусков.
- Учебные экраны обновляют `Portal.state` и вызывают `Portal.save()`. Отправная точка для аналитики — `Portal.record(event)`. Переходы выполняются через `Portal.go(route)`.
- `dist/team.js` строит отчёт руководителя по фактически сохранённым событиям. Состояние текущего профиля и загруженные отчёты хранятся в браузере. Для переноса на другой компьютер экспортируйте JSON через кабинет руководителя.
- Локальная панель открывается по адресу `#/team`. Перед производственным запуском добавьте серверную авторизацию, разграничение доступа к отчётам и корпоративные сроки обучения.

## Формат отчёта v1

Экспорт содержит `format: "kmg-learning-report"`, `version: 1`, `exportedAt` в ISO 8601 и объект `profile`. В профиле есть `id`, `name`, `completed` (массив ключей вида `courseId/lessonId`), `last`, `deadline` (`YYYY-MM-DD` или пустая строка) и `events`. Экспорт предназначен для аналитики попыток. Для полноценной синхронизации обучения потребуется переносить также карточки, позиции видео и состояния незаконченных заданий.

| Поле события | Назначение |
|---|---|
| type | `answer` для задания, `video-answer` для решения в шортсе |
| courseId, lessonId, questionId | Связь с контентом. Для шортса используется идентификатор вопроса |
| correct, response | Исход попытки и выбранный ответ |
| elapsed | Активное время ответа в секундах, `null` при отсутствии замера |
| hints, attempt | Число использованных подсказок и номер попытки |
| ts | Временная отметка, если передана производителем события |

Повторный импорт по одному `profile.id` заменяет отчёт более свежим снимком. Дубли и устаревшие снимки пропускаются. Срок, назначенный импортированному сотруднику, действует в кабинете руководителя на этом устройстве. Текущий профиль защищён от замены при импорте его собственного файла. Точность в таблице считается по первым ответам на учебные вопросы. Время сравнивается по медиане первых попыток на одном вопросе, с указанием числа участников. Решения в видео входят в историю сотрудника отдельно.

## Подключение бэкенда

1. Замените локальный идентификатор сотрудника идентификатором корпоративной учётной записи. Назначайте роли и проверяйте права на сервере.
2. Подключите загрузку состояния при старте. Для событий добавьте уникальный идентификатор попытки и очередь отправки после локального сохранения. Уникальный ключ на сервере предотвратит повторную запись при восстановлении связи.
3. Получайте состав команды, дедлайны и агрегаты из базы. Для офлайн-режима сохраните экспорт/импорт и локальный прогресс. Синхронизация между устройствами по сети требует отдельной реализации.
4. Подключите сервис ИИ-подсказок, передавая текущий шаг и подтверждённые источником сведения. Ключи сервисов храните на сервере. Локальные подсказки должны оставаться доступны офлайн.

Сайт представляет фронтенд проекта с демонстрационным учебным наполнением. Для сдачи всего кейса отдельно необходимы автоматический конвейер обработки незнакомых глав, проверка полноты покрытия и качества, версии источников и журнал ручных правок.
